"Collection = learned" is the biggest illusion in modern times.

I have hundreds of "read later" articles in my favorites, but I haven't opened any of them. Later I changed my approach and the situation improved a lot.

## What's the problem

The problem with fragmented reading is not "read less", but that things read cannot be found and used again.

Three specific obstacles:

1. **No trigger point**: I encountered a related problem three months later and couldn’t remember reading it.
2. **No context**: I only saved the link and forgot why I found it useful at the time.
3. **No reusable unit**: The entire article is too long, and the cost of re-reading is higher than re-searching

## three actions

### Action 1: Leave only one sentence when reading

After reading it, immediately write a sentence: **"What does this article say and how is it useful to me"**.

Fixed format:

```
[主题] 一句话结论 —— 可用在：具体场景
```

for example:

```
[性能] 虚拟列表在超过 200 行时收益明显 —— 可用在：长列表页面
[写作] 先写结论再补论证，读者更容易跟上 —— 可用在：技术文档
```

**The key is to have the "available for" half**. Without it, the sentence will be worthless three months later.

### Action 2: Keep only the reusable parts

Usually only 10% of an article is worth retaining. **Extract** that part instead of saving the entire article.

- piece of code → save as a runnable fragment
- A criterion for judgment → Save as a sentence
- A set of data → save as a table

Judgment criteria: **Can it be used directly next time it is used? ** If it can’t, it means we didn’t pick enough.

### Action 3: Merge similar items regularly

Spend twenty minutes each month combining similar sentences into a theme document.

The fragments of ten articles talking about "performance optimization" may be combined into a "performance checklist" - this is when it is really useful.

## A counter-intuitive suggestion

**Most things are not worth keeping. **

After reading it, if you think it's "somewhat interesting" but can't tell "where it can be used", just delete it. The stricter the criteria for retention, the more useful the things left behind will be.

My ratio is roughly: read 10 articles and retain part of 1 article.

## Specific process

```
读到一篇
  ↓
读完立刻写一句话（含「可用在」）
  ↓
判断：有可复用单元吗？
  ├─ 没有 → 删掉
  └─ 有 → 摘出来，放进主题文件
  ↓
每月合并同类项
```

## Tools are not important

Obsidian, Notion, and plain text folders will all work. What really works are **three actions**:

1. Write a sentence immediately after reading (reduce forgetting)
2. Extract only the reusable parts (reduce re-reading costs)
3. Periodic merging (generating structures)

Tools only affect efficiency, not whether it happens.

## a test method

Ask yourself: What you read last month, have you used it this month? **

- Used → The process is valid
- Can’t remember what I’ve read → Only “read”, not “stay”

## summary

| stage | action | output |
|---|---|---|
| while reading | Write a sentence + available scenarios | searchable index |
| After reading | Extract reusable units | Materials that can be used directly |
| per month | Merge similar items | structured knowledge |

**Collection is an action, not a result. **
