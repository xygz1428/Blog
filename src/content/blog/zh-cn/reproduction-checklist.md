复现别人的实验，最常见的结局是「跑通了，但数字对不上」。

先别怀疑论文造假——**八成是某个环节的细节没对上**。下面按排查顺序列出。

## 第一层：环境

- [ ] 依赖版本是否与论文一致（`requirements.txt` / `environment.yml` 有没有）
- [ ] Python / CUDA / 框架版本
- [ ] 硬件差异（不同 GPU 型号可能导致数值差异）
- [ ] 随机性来源是否固定（种子、`cudnn.deterministic`、多线程顺序）

**经验**：框架大版本差异经常导致指标差 1–2 个点，小版本差异通常可忽略。

## 第二层：数据

- [ ] 数据集版本（同一个名字可能有多个修订版）
- [ ] 划分方式（随机划分还是固定划分？种子是什么？）
- [ ] 预处理细节（归一化参数是用训练集算的还是全体算的）
- [ ] 类别不平衡的处理方式
- [ ] 数据泄漏检查（预处理有没有用到测试集信息）

**最容易错的地方**：预处理顺序。先划分再归一化，和先归一化再划分，结果会不一样。

## 第三层：训练细节

- [ ] 学习率、调度策略、warmup
- [ ] batch size（影响梯度的噪声尺度）
- [ ] 训练轮数 / 早停策略
- [ ] 优化器与它的默认参数（β、eps 经常被忽略）
- [ ] 权重初始化方式
- [ ] 梯度裁剪

**注意**：改了 batch size 往往要同步调学习率，否则不是公平对比。

## 第四层：评估口径

- [ ] 指标定义（同一个名字在不同论文里定义可能不同）
- [ ] 是否取多次运行的最优值（`best of k`）还是均值
- [ ] 测试时是否用了数据增强（TTA）
- [ ] 阈值怎么定的（在验证集上选还是固定）

**这一步最容易被忽略**。很多「复现不出来」其实是口径不同：论文报的是 5 次里最好的，你报的是单次。

## 排查策略

**不要同时改多个变量**。按这个顺序：

1. 先确认能跑通（哪怕指标很差）
2. 对齐评估口径，看数字是否接近
3. 对齐数据划分
4. 再调超参数

每改一项，记录指标变化。这样最后能定位到是哪一项造成的差异。

## 差异多大算正常

| 差异 | 判断 |
|---|---|
| < 1% | 正常波动，可接受 |
| 1–3% | 需要找原因，但不必怀疑论文 |
| > 5% | 大概率有环节没对齐 |
| 方向相反 | 优先怀疑数据或评估口径 |

具体阈值取决于任务本身的方差——方差大的任务（小数据集、强随机性）容忍度更高。

## 复现不了怎么办

**先写下来你试了什么**。这份记录本身有价值：

- 哪些环节对齐了、哪些没有
- 差异出现在第几步
- 你的猜测

然后可以做的事：

1. 找作者要代码或配置（很多论文有附录或补充材料）
2. 在社区提问，附上你的完整配置
3. 如果差异稳定且可解释，把它写进你自己的论文作为讨论

**复现失败不等于论文有问题**，但**无法解释的差异值得记录**。

## 小结

复现的顺序应该是：**环境 → 数据 → 训练 → 评估口径**。

从最外层开始对齐，每步只改一个变量，把每次的结果记下来。这样即使最终没复现出来，你也知道卡在哪一层。
