# 什么样的博客是优秀的

> 这份文档试图把「好看」「好用」这类模糊判断，换成可测量、可对照的标准。
> 数据来自对 14 个公认优秀博客的实测（HTTP 状态、CSS 取值、页面体积），不是凭印象总结。

## 一、先给结论

优秀的博客要过三关，顺序不能颠倒：

| 层次 | 问题 | 失败后果 |
|---|---|---|
| **1. 能被找到** | 搜索引擎能收录吗？分享出去有预览吗？ | 没人看得到 |
| **2. 能被读完** | 打开快吗？读着累吗？ | 打开了也读不下去 |
| **3. 值得回来** | 内容有长期价值吗？ | 读完就走，不再来 |

**大多数博客死在第二关**——内容不错，但排版劝退。

## 二、可测量的硬指标

### 正文行宽：650–900px

这是实测出来的共识区间（单位 px，取各站主容器的常见值）：

| 站点 | 正文容器宽度 |
|---|---|
| gwern.net | 649 |
| jvns.ca | 531 |
| craigmod.com | 520 / 768 |
| lilianweng.github.io | 768 / 900 |
| simonwillison.net | 680 / 800 / 940 |
| nathanchen.me | 800（`65%`，`max-width: 800px`） |

**为什么是这个区间**：一行超过约 90 个字符，眼睛换行时容易串行；低于 40 个字符，换行太频繁，节奏被打断。

中文同理——700px 左右、18px 字号，一行大约 35–40 个汉字，正好。

### 正文字号：16–20px

实测：gwern 18/20px、nathanchen 18px、simonwillison 16px、lilianweng 16px。

**低于 16px 是在惩罚读者**。中文尤其如此——汉字笔画密，比拉丁字母更需要大字号。

### 行高：1.5–1.75

实测集中在 1.4–1.6。中文通常需要比英文更高一点，1.7–1.8 是可接受区间。

### 每页请求：越少越好

优秀的个人博客普遍是**纯静态、零框架、零追踪**：

- gwern.net：单页 HTML + 少量 CSS，无 JS 框架
- jvns.ca：纯静态
- 我们的站：单页 HTML 中位数 **6.8 KB**，CSS 总计 42 KB，**无独立 JS 文件**

对照：一个带分析脚本 + 字体 CDN + 广告的博客，单页轻松超过 1 MB。

### 首屏不能闪

深浅色主题必须在**首次绘制前**定好，否则用户会看到一帧白底再变黑。做法是 `<head>` 里的内联脚本读 `localStorage` + `prefers-color-scheme`。

## 三、视觉上的共性

实测两个代表性站点的 CSS 变量，发现共同点不是「好看」，而是**克制**：

### 配色：少即是多

**darkkandaomaster.com** 的真实色板：

```css
--paper: #f5f1ea;      /* 暖纸，不是纯白 */
--ink: #1f1b17;        /* 暖黑，不是纯黑 */
--apricot: #e2672b;    /* 唯一的强调色 */
```

整站**没有冷色**。强调色只有一个，其余全是暖灰阶。

**nathanchen.me** 更极端：纯白底 + 纯黑字 + 灰色链接，几乎没有色彩。

**规律**：优秀博客的强调色通常 ≤ 1 个。超过三个颜色，页面就开始显得廉价。

### 留白：竖向节奏要拉开

darkkandaomaster 的 section 间距：

```css
padding: clamp(72px, 10vw, 140px) var(--gutter) 0;
```

nathanchen 的内容起始位置：`margin-top: 14vh`。

**共同点**：大段留白，而不是把内容塞满。留白本身是排版的一部分。

### 字体：一到两套，不混用

| 站点 | 字体选择 |
|---|---|
| nathanchen.me | Spectral（衬线）+ Jost（无衬线） |
| Lipi | Literata（衬线）+ Manrope（无衬线） |
| darkkandaomaster | Kandao Serif（自建）+ Instrument Serif |

**规律**：正文一套、界面一套，最多两套。

**反例**：为了"设计感"引入四五种字体，加载慢且视觉混乱。

### 交互细节：只在有用处出现

Lipi 的实测类名里有 `reading-progress-bar` 和 `scroll-to-top`——两个极小的功能，但对长文阅读有实际帮助。

**判断标准**：这个动效/组件是否帮读者完成某件事？不帮就别加。

## 四、内容层面的标准

排版只决定「读不读得下去」，内容决定「值不值得来」。

### 1. 有具体细节

好的技术文章包含：真实报错信息、具体版本号、可复制的命令、踩坑的具体路径。

**反例**：「要注意性能优化」——正确但无用。

### 2. 有判断，不只是罗列

「A 和 B 的区别」是资料；「我在什么场景下选了 A，因为……」是经验。

读者来个人博客，要的是后者。

### 3. 有边界

好的文章会说清「这个方法在什么情况下不适用」。

**这是区分「抄文档」和「真用过」的关键。**

### 4. 可检索

标题包含关键词，有小标题，有目录。三个月后自己也能搜到。

## 五、十个反模式

| 反模式 | 为什么是问题 |
|---|---|
| 自动播放音乐/视频 | 打断阅读，且无法预测 |
| 弹窗订阅 | 在读者最投入时打断 |
| 无限滚动 + 广告 | 无法判断内容边界 |
| 花哨的滚动动画 | 滚轮被劫持，读者失去控制感 |
| 正文用浅灰色（对比度 < 4.5:1） | 直接损害可读性 |
| 每段都配一张无关大图 | 稀释信息密度 |
| 字体小于 16px | 惩罚读者 |
| 没有 RSS | 剥夺订阅方式 |
| 强制登录才能读 | 对个人博客毫无必要 |
| 追踪脚本一堆 | 慢，且消耗信任 |

## 六、自检清单

发布前问自己：

**可发现性**
- [ ] 每篇有独立的 `title` 和 `description`？
- [ ] 有 sitemap 和 RSS？
- [ ] 分享出去有预览图（OG image）？

**可读性**
- [ ] 正文行宽在 650–900px？
- [ ] 字号 ≥ 16px，行高 ≥ 1.5？
- [ ] 深浅色都能读（对比度 ≥ 4.5:1）？
- [ ] 手机上好读（不是把桌面版缩小）？
- [ ] 首屏没有闪白、没有弹窗？

**内容**
- [ ] 有具体细节（数字、报错、命令）？
- [ ] 说了自己的判断，而不只是罗列？
- [ ] 写清了适用范围/局限？

## 七、拿我们自己的博客对照

诚实打分，不美化。

| 项 | 实测值 | 标准 | 判断 |
|---|---|---|---|
| 正文行宽 | 44rem ≈ 704px | 650–900px | ✅ |
| 正文字号 | 18px | ≥ 16px | ✅ |
| 行高 | 1.8 | 1.5–1.75 | ⚠️ 略高，中文可接受 |
| 单页 HTML | 6.8 KB（中位数） | 越小越好 | ✅ |
| 独立 JS 文件 | 0 | 少 | ✅ |
| 追踪脚本 | 0 | 0 | ✅ |
| 深浅色 | 支持，首屏无闪白 | 支持 | ✅ |
| RSS / sitemap | 都有 | 有 | ✅ |
| OG 预览图 | **没有** | 有 | ❌ |
| 文章数 | 25 篇 | 持续更新 | ⚠️ 刚起步 |
| 英/繁翻译 | 各 1 篇 | 按需 | ⚠️ 样例级别 |
| 评论 | 无 | 可选 | — |

**已修复**：OG 分享图已补上。**已知短板**：英文文章只有 1 篇（中文 25 篇）。

## 八、一句话总结

**优秀的博客 = 让读者以最低的摩擦读到有价值的东西。**

排版负责「摩擦低」，内容负责「有价值」。两者缺一不可，但**排版是及格线，内容才是天花板**。
