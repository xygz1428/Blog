# 留言功能配置

留言区已接好（giscus，基于 GitHub Discussions），但**需要你完成三步**才能启用。

在完成配置前，文章页会显示「留言功能待配置」的提示，不会报错。

## 为什么用 giscus

| 方案 | 需要服务器 | 需要你的账号操作 | 支持先审后发 |
|---|---|---|---|
| **giscus**（当前方案） | ❌ | 安装一个 GitHub App | ❌（可事后删除） |
| Waline | ✅ 部署到 Vercel | 注册 Vercel | ✅ |
| Twikoo | ✅ 腾讯云开发 | 注册腾讯云 | ✅ |
| Staticman | ❌ | 配置 PR 流程 | ✅（读者需 GitHub 账号） |

选 giscus 的原因：**纯静态、免费、不需要服务器**，评论存在你自己仓库的 Discussions 里，数据归你。

**代价**：读者必须有 GitHub 账号；评论发布后立即显示，审核方式是事后删除或隐藏。

## 配置步骤

### 1. 开启 Discussions 并建分类

仓库 → **Settings** → **General** → 勾选 **Discussions**。

然后在仓库的 **Discussions** 页 → 分类旁的齿轮 → 新建分类，名字填 **`Comments`**（类型选 Announcements 或 Open 都可以）。

### 2. 安装 giscus App

打开 https://github.com/apps/giscus → **Install** → 选择你的账号 → 勾选 `Blog` 仓库。

### 3. 拿到两个 ID

打开 https://giscus.app/zh-CN ：

- **仓库**填 `xygz1428/Blog`
- **Discussion 分类**选 `Comments`
- 页面下方会生成一段配置代码，里面有两行：

```html
data-repo-id="R_kgDOxxxxxxx"
data-category-id="DIC_kwDOxxxxxxx"
```

### 4. 填进 site.mjs

打开 `src/site.mjs`，把两个值填进去：

```js
const GISCUS = {
  repo: 'xygz1428/Blog',
  repoId: 'R_kgDOxxxxxxx',        // ← 填这里
  category: 'Comments',
  categoryId: 'DIC_kwDOxxxxxxx',  // ← 填这里
};
```

保存后推送：

```bash
git add .
git commit -m "feat: 启用留言"
git push
```

约一分钟后线上文章的底部就会出现留言框。

## 关于「审核」

giscus 本身**没有先审后发**。可用的控制手段：

| 手段 | 做法 |
|---|---|
| 事后删除 | 在仓库 Discussions 里直接删除评论 |
| 锁定讨论 | 对某个 Discussion 点「Lock conversation」 |
| 限制互动 | Settings → Moderation 里设置 interaction limits |
| 关闭留言 | 把 `repoId` 清空，文章页回到「待配置」提示 |

**如果你确实需要「先审后发」**，那就得换 Waline（部署到 Vercel，配置项里 `COMMENT_AUDIT: true`）。需要的话告诉我，我改成 Waline。

## 主题与语言

- 主题：`preferred_color_scheme`，跟随系统深浅色
- 语言：简体页面用 `zh-CN`，英文页面用 `en`

## 隐私说明

留言加载时浏览器会请求 `giscus.app` 与 GitHub 的接口。**只有滚动到文章底部时才会加载**（`data-loading="lazy"`），不影响正文阅读。

这一点已写进 `免责声明` 页面。
