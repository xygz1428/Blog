## ADR-001 用 Astro 7 而不是 Next.js / Hugo

**背景**：要一个能长期维护、免费托管、以写作为主的个人站。

**选择**：Astro 7，静态输出。

**理由**
- 默认零客户端 JS，页面就是 HTML + CSS，首屏快
- 内容集合（Content Collections）带 schema 校验，frontmatter 写错会构建失败而不是静默出错
- Markdown 一等公民，不需要为写作额外配置

**放弃的方案**
- **Next.js**：为博客引入 React 运行时与构建复杂度，收益为零
- **Hugo**：构建极快，但 Go 模板语法上手成本高，改样式要学一套 DSL

**代价**
- Astro 7 较新，生态与文档还在跟进；本项目中已踩到「默认 Markdown 处理器换了、`remarkPlugins` 需要额外装 `@astrojs/markdown-remark`」

## ADR-002 手写 CSS，不引 UI 框架

**背景**：博客样式不复杂，但要长期维护、不能因为依赖升级而崩。

**选择**：单文件 `global.css` + CSS 变量。

**理由**
- 无构建步骤、无版本升级风险
- 体积小：全站 CSS 约 17 KB（含 KaTeX 后 35 KB）
- 改样式就是改 CSS，不需要理解框架的抽象层

**放弃的方案**
- **Tailwind**：多一层依赖与配置；类名堆在模板里，长期维护反而更难读
- **组件库**：博客用不到那么多组件，引入是负担

**代价**
- 没有现成的响应式工具类，媒体查询要手写
- 类名需要自己维护一致性（已用命名前缀缓解，如 `__rb_`、`post-`）

## ADR-003 搜索用自建 JSON 索引

**背景**：需要站内搜索，但不能有后端。

**选择**：构建期生成 `search.json`，前端拉取后做词面匹配。

**理由**
- 零外部服务、零账号、零费用
- 当前 4 篇文章，索引只有约 2.4 KB
- 完全可控：匹配逻辑（标题权重 5 / 标签 3 / 摘要 2 / 正文 1）写在页面里，随时可调

**放弃的方案**
- **Algolia**：要注册账号、有配额、数据出本机
- **Pagefind**：更专业（带词干、分片加载），但会引入构建步骤和索引文件；当前规模不值得

**代价**
- 词面匹配，不理解语义，也不做中文分词
- 文章变多后索引会线性膨胀

**何时该换**：文章超过 30 篇，或用户抱怨搜不到。换 Pagefind 时只需替换 `search.json.js` 与 `search.astro` 的取数逻辑。

## ADR-004 图片走 Astro 优化管线

**背景**：文章需要插图，且站点部署在 `/Blog/` 子路径下。

**选择**：图片放 `src/content/blog/images/`，Markdown 里用 `./images/x.png` 相对路径。

**理由**
- 构建期解析相对路径，**自动补上 base 前缀**，不会 404
- 自动转 WebP 并压缩：实测一张 46 KB 的 PNG 压到 19 KB
- 自动加 `loading="lazy"`、`width`/`height`（避免布局跳动）

**放弃的方案**
- **`public/images/` + 绝对路径**：文章里必须手写 `/Blog/images/x.png`，一旦改仓库名就全站图片失效
- **外部图床**：多一个依赖，且国内图床稳定性参差

**代价**
- 图片必须放在指定目录，不能和文章放一起（共享目录，命名需自己避免冲突）
- 原图不进产物，需要保留源文件在仓库里

## ADR-005 主题用 `data-theme` + CSS 变量

**背景**：需要深浅色切换，且不能有闪白。

**选择**：`:root` 定义浅色变量，`:root[data-theme='dark']` 覆盖；首屏内联脚本定主题。

**理由**
- 一套样式表切换两套配色，不重复维护
- 内联脚本在首次绘制前执行，无闪白
- 记住用户选择（`localStorage['blog-theme']`），首次访问跟随系统

**放弃的方案**
- **两套独立样式表**：重复度高，改一处要改两遍
- **只用 `prefers-color-scheme`**：无法让用户手动覆盖系统设置

**代价**
- 新增颜色必须同时加到两个块里，漏了会在某个主题下显示异常

## ADR-006 公式在构建期渲染（KaTeX）

**背景**：科研类文章需要数学公式。

**选择**：`remark-math` + `rehype-katex`，构建期渲染成 HTML；同时引入 `katex.min.css`。

**理由**
- 构建期渲染，浏览器不需要加载 MathJax 运行时
- 排版精确，行内与块级都支持

**放弃的方案**
- **MathJax**：运行时渲染，首屏会闪一下公式，且体积大
- **图片化公式**：不可搜索、不可复制、暗色模式要出两套图

**代价**
- 增加约 35 KB CSS + 19 个字体文件
- Astro 7 起默认处理器不再内置公式支持，必须显式装 `@astrojs/markdown-remark`

## ADR-007 部署用 GitHub Actions 而非 gh-pages 分支

**背景**：需要推送即部署，且不想手动构建上传。

**选择**：GitHub Actions 构建 + `upload-pages-artifact` + `deploy-pages`。

**理由**
- 官方推荐路径，不需要维护 `gh-pages` 分支
- 构建日志在 Actions 页可见，失败能定位
- 权限最小化：`contents: read` / `pages: write` / `id-token: write`

**放弃的方案**
- **`gh-pages` 分支**：需要本地构建后推产物，容易忘记构建、且产物进版本历史

**代价**
- 依赖第三方 Action 版本（`actions/checkout@v4` 等），未来需要跟进升级
- **CI 用 `npm install` 而非 `npm ci`**：Windows 生成的 lockfile 缺少 Linux 需要的 `@emnapi/*` 实体条目，`npm ci` 会硬失败（详见 `踩坑记录.md` 第 1 条）
