# 写作指南

这份文档面向「不想碰代码，只想写字」的场景。照着做就行。

## 一、新建一篇文章

打开终端，进入博客目录：

```bash
cd D:\KProject\Blog
npm run new "我的第一篇文章"
```

会在 `src/content/blog/` 下生成一个文件，名字是时间戳（例如 `2026-11-26-230422.md`），里面已经写好了骨架。

**文件名的用途**：它就是网址路径。
`2026-11-26-230422.md` → `/blog/2026-11-26-230422/`

想改网址？直接改文件名即可（建议用英文短横线风格，如 `my-first-post.md`）。

## 二、frontmatter 字段

文件顶部两个 `---` 之间是配置区：

```yaml
---
title: 文章标题              # 必填
description: 一句话摘要       # 选填，用于列表、RSS、搜索结果
pubDate: 2026-11-26          # 必填，格式必须 YYYY-MM-DD
updatedDate: 2026-11-27      # 选填，有实质更新时填
category: 技术               # 必填，只能是：科研 / 技术 / 学习 / 生活
tags: ['Astro', '建站']       # 选填，方括号里逗号分隔
draft: true                  # 草稿开关，见第五节
---
```

**写错会构建失败**——这是好事，能防止文章默默消失。构建报错会指出是哪个文件的哪个字段。

## 三、放图片

### 硬规则

图片**必须**放在：

```
src/content/blog/images/
```

引用时**必须**用 `./images/` 开头的相对路径：

```markdown
![图片说明](./images/我的图片.png)
```

### 为什么不能写 `/images/xxx.png`

本站部署在 `https://<用户名>.github.io/Blog/` 这个**子路径**下。

- 写 `./images/x.png` → 构建时自动补成 `/Blog/_astro/x.哈希.webp` ✅
- 写 `/images/x.png` → 指向域名根，**必然 404** ❌

### 图片会被自动优化

构建时 Astro 会把图片转成 WebP 并压缩。实测：一张 46 KB 的 PNG 压到 19 KB，同时自动加 `loading="lazy"` 和宽高属性（避免布局跳动）。

**原图不会进仓库产物**，所以原图可以直接放高清版本。

### 图注

图片的**下一行**写一对星号包住的文字：

```markdown
![示意图](./images/demo.png)

*这是图注，会显示成居中的小字*
```

### 点击放大

正文里的图片点一下会弹出大图，点任意处或按 Esc 关闭。不需要额外写任何东西。

## 四、公式、代码、表格

**行内公式**：`$E = mc^2$` → $E = mc^2$

**块级公式**（前后要空行）：

```markdown
$$
\hat{\beta} = (X^{\top}X)^{-1}X^{\top}y
$$
```

**代码块**：三个反引号加语言名，右上角会有复制按钮。

**表格**：标准 Markdown 表格即可。

## 五、草稿与发布

`draft: true` 时：

- 不出现在文章列表
- 不出现在首页、归档、标签页
- 不进 RSS

本地预览草稿：把 `draft` 改成 `false`，跑 `npm run dev` 看效果，看完再改回 `true`。

**正式发布**：

```bash
git add .
git commit -m "post: 文章标题"
git push
```

推送后 GitHub Actions 自动构建发布，大约一分钟。

## 六、本地预览

```bash
npm run dev
```

打开 **http://localhost:4321/Blog/**（注意要带 `/Blog/`）。

改文件会自动刷新。

## 七、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 图片显示不出来 | 路径写成了 `/images/...` | 改成 `./images/...` |
| 图片显示不出来 | 图片没放在 `src/content/blog/images/` | 挪进去 |
| 文章不显示 | `draft: true` | 改成 `false` |
| 构建失败，报 category | 分类写错了 | 只能是 科研/技术/学习/生活 四选一 |
| 构建失败，报 pubDate | 日期格式错 | 必须是 `2026-11-26` 这种格式 |
| 部署后还是旧内容 | Actions 还没跑完 | 去仓库 Actions 页看进度 |
| 样式丢失 / 全站 404 | `src/site.mjs` 的 `base` 和仓库名不一致 | 两者必须相同 |

## 八、写完之后

文章目录会自动生成（h2/h3 标题）、阅读时长会自动计算、标签页会自动创建——**这些都不用你管**。
